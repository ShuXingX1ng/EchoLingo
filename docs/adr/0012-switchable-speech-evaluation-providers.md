# Use EchoLingo-only and explicit comparison modes for Read Aloud

EchoLingo is currently a personal learning project without real users, so once the self-trained Speech Evaluator passes basic integration acceptance it becomes the default Read Aloud evaluator during development instead of remaining invisible in shadow mode. Azure Pronunciation Assessment is retained as an external comparison baseline rather than removed or treated as training truth.

The first Read Aloud flow exposes two Speech Evaluation Modes: `echolingo` runs only the self-trained evaluator and `compare` explicitly runs both providers against the same recording. Azure-only evaluation and automatic Azure fallback are not exposed for Read Aloud because they would hide self-trained failures and weaken diagnosis; the Azure adapter remains available to comparison tests. Repeat Sentence retains its current Azure assessment until a separately labelled and calibrated task-specific evaluator exists, and Azure TTS is unaffected.

EchoLingo becomes the learning-phase default only after Speech Evaluator Acceptance: speaker-isolation and data audits pass, two equivalent training runs are reasonably stable, sentence accuracy and fluency each reach at least 0.60 correlation with held-out SpeechOcean expert labels, sentence/word/phoneme predictions beat non-learning baselines, invalid or unalignable audio fails safely, and the Azure comparison adapter remains operational. These are engineering gates for a personal development default, not PTE calibration or public-release criteria.

The public contract is provider-neutral rather than the current Azure-shaped `accuracyScore` / `fluencyScore` / `completenessScore` response. A new speech-evaluation endpoint returns task score, Pronunciation, Oral Fluency, Content, recognized content, word or phoneme evidence, and evidence availability; FastAPI adapters map both EchoLingo and Azure into it. The Azure-specific pronunciation endpoint is migration-only and can be removed after the frontend no longer depends on it.

Comparison mode retains structured provider results, score differences, evidence availability, checkpoint identity, timestamps, and an irreversible recording hash by default, not raw audio, frame features, reusable embeddings, MFA temporary files, or duplicate prompt text. An explicit local debug option may retain the developer's own audio for a bounded period; future user audio retention and any training use remain separately consented.

The first endpoint is synchronous with a 30-second local budget. Comparison calls providers concurrently and may return a partial result when one provider fails; EchoLingo-only failure is reported explicitly and never relabelled or silently replaced by Azure. A queue or streaming progress protocol is introduced only if measured runtime makes the synchronous contract unsuitable.

The evaluator and calibration policy alone produce scores and structured factual findings. A deterministic explanation layer turns supported word, phoneme, omission, pause, and timing findings into auditable statements, while the existing Feedback LLM may improve teaching language and suggestions but cannot alter scores, introduce an unobserved error, or claim unavailable evidence; Tutor Conversation later consumes the same result rather than scoring again.

Read Aloud presents complete reliable evidence at word and fluency-event level: all reliably weak words are marked, omissions, insertions, and repetitions have distinct states, and significant pauses or repairs are located in context. Clicking a weak word shows its score and a concise supported problem category, not the full phoneme inventory; phoneme scores, spans, and alignment diagnostics remain available to developer analysis and a future specialist pronunciation feature, while a short summary prioritises what to practise first.

Comparison output is rendered only on a developer diagnostic surface, with side-by-side dimensions, deltas, recognized text, disputed word findings, alignment state, provider latency, and provider errors. The ordinary Read Aloud feedback surface always shows one primary result so learners are not asked to interpret conflicting provider judgements.
