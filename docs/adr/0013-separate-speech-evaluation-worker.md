# Run the Speech Evaluator in a private GPU worker

EchoLingo's existing FastAPI deployment is a lightweight CPU-oriented public backend, while Wav2Vec2, MFA, PyTorch/CUDA, and evaluator checkpoints introduce large and specialised runtime dependencies. The self-trained model therefore runs in a separate private Speech Evaluation Worker; FastAPI remains the only browser-facing authority and owns authentication, request validation, Speech Evaluation Mode routing, response contracts, and explicit comparison-provider orchestration.

Training and inference are separate processes. Training uses the local RTX 4070 to produce a checkpoint bundle, while the worker loads one selected bundle and uses the GPU for inference; during personal development it listens on a configurable private address whose default is `http://localhost:8100`. The port is not model storage or model identity, and a future cloud GPU worker can replace the local process without changing the public frontend contract.

Each accepted model is an immutable Evaluator Checkpoint Bundle containing scoring and optional adapter weights, pinned upstream revision, model and feature schemas, label scales, normalization, training and dataset manifests, benchmark results, code revision, and licence notices. The worker loads an explicit bundle identifier from configuration and never discovers the newest file automatically; large weights stay outside ordinary Git so version selection, rollback, and reproducibility do not depend on repository history.

Training, preprocessing, evaluation, bundle handling, and the private worker share one top-level `speech/` Python package in the existing monorepo so training and inference cannot drift into copied implementations. The public `backend/` adds only a lightweight HTTP client and provider orchestration and does not acquire PyTorch, CUDA, Transformers, MFA, or MLflow dependencies; speech data and artifacts live outside Git behind configured root directories.

The standard local speech environment is an isolated WSL2 Ubuntu environment using the host RTX 4070 through the Windows NVIDIA driver. PyTorch/CUDA, MFA, MLflow, training, and the worker stay inside that environment; Linux display drivers are not installed in WSL, large speech data and caches prefer the WSL filesystem, and the Windows-hosted FastAPI reaches the private worker through its configured localhost address.
