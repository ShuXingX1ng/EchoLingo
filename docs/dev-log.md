### Environment Variables

Create `.env.local` in the project root with:

```
LLM_API_KEY=your_api_key_here
LLM_BASE_URL=https://api.openai.com/v1
LLM_MODEL=gpt-4o-mini
```

Compatible providers:
- OpenAI: `https://api.openai.com/v1`
- Together AI: `https://api.together.xyz/v1`
- Groq: `https://api.groq.com/openai/v1`
- Ollama (local): `http://localhost:11434/v1`

### How to Test

1. Add your API keys to `.env.local` as shown above.
2. Run `npm run dev`.
3. Open http://localhost:3000/practice.
4. The examiner should ask: "Let's talk about your hometown. Where is your hometown?"
5. Type an answer and click **Send** (or press Enter).
6. Wait for the AI examiner to respond with a follow-up question.
7. Continue for 3-5 turns.
8. Click **End Session**.
9. Wait for feedback to generate (a loading indicator will show).
10. A feedback modal should appear with your estimated band score, detailed feedback, and improvement suggestions.

### Notes and Assumptions

- OpenAI-compatible API format: All endpoints use `/chat/completions` with Bearer token auth, which works with OpenAI, Groq, Together, Ollama, etc.
- JSON mode for feedback: The feedback endpoint uses `response_format: { type: "json_object" }` which is supported by OpenAI and some compatible providers. If your provider doesn't support this, the LLM may still return valid JSON but it's less guaranteed.
- Initial question is hardcoded: The first examiner question is still hardcoded on the client side ("Let's talk about your hometown. Where is your hometown?"). All subsequent questions come from the LLM.
- No streaming: Responses are returned in full (not streamed) to keep the implementation simple.
- Error handling: If the API call fails, an error message appears in the chat. The user can click "Start New Session" to retry.
- Feedback is a modal: The feedback displays as a full-screen modal overlay rather than a separate page, as specified in the product spec.

### Completed Work

**localStorage Utility (`src/lib/history.ts`):**

**History Page (`/history`):**

- Shows empty state with "Start Your First Session" link when no history exists.

- Imports `saveSession` from history utility.
- Saves session to localStorage immediately after feedback is generated.
- Added "History" link in the header next to "End Session" button.

**Landing Page Updates:**
- Added "View History" button next to "Start Practice" button.
- Both buttons are visually distinct (filled vs outlined style).

### How to Test

1. Run `npm run dev` and open http://localhost:3000.
2. Click "Start Practice" and complete a practice session.
3. After feedback is generated, the session is automatically saved.
4. Navigate to /history (or click "History" link in practice header).
5. Verify the completed session appears in the list with date, band score, and preview.
6. Click the session to view full transcript and feedback.
7. Click "Back" to return to the list.
8. Click "Start New Session" to begin another practice.
9. Complete multiple sessions and verify they all appear in history (newest first).

### Notes and Assumptions

- localStorage only: All data is stored in the browser's localStorage. No cloud database or user login.
- Client-side only: The history page uses `"use client"` directive and loads data via useEffect to avoid SSR issues with localStorage.
- No delete functionality: Users cannot delete individual sessions from history (can be added later).
- No export functionality: Session data cannot be exported (can be added later).
- Data persistence: Sessions persist across browser tabs and page refreshes, but are cleared if the user clears browser data.
- Session ordering: Sessions are stored with newest first by prepending to the array.
